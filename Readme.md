# Empirical Privacy Without Differential Privacy

## ImageCLEFmedical GANs 2026: Fingerprint Detection, Latent-Space Analysis, and Privacy-Preserving CT Generation

This repository contains the CSMorgan Lab notebooks for the **ImageCLEFmedical GANs 2026** challenge. The project studies privacy leakage, memorisation, latent-code recoverability, and privacy-preserving synthetic CT generation using generative models and representation-learning methods.

The work supports the paper:

**Empirical Privacy Without Differential Privacy: A Privacy–Utility Frontier Analysis of Synthetic CT Generation**

## Overview

AI systems for medical diagnosis often require large and diverse datasets. However, access to real medical images is limited by privacy regulations, ethics, and patient consent restrictions. Synthetic medical data generated by models such as GANs and diffusion models offers a potential solution, but only if the generated images do not preserve hidden traces, fingerprints, or patient-specific details from the original training data.

This project investigates that problem through the ImageCLEFmedical GANs 2026 benchmark, which focuses on three complementary privacy-related subtasks:

1. **Detecting training data usage**
2. **Identifying corresponding latent vectors**
3. **Generating privacy-preserving CT slices**

The main contribution of this repository is an empirical privacy-focused pipeline for synthetic CT generation, alongside negative but informative results for membership inference and latent matching.

## Challenge Background

The ImageCLEFmedical GANs task investigates whether synthetic medical images preserve traces of real training data. Previous editions showed that generative models can retain fingerprints of their training datasets, raising concerns about privacy leakage, memorisation, and model attribution.

The 2026 edition extends this line of work by introducing three subtasks:

* image-level training-data usage detection
* latent-vector matching for synthetic images
* privacy-preserving CT slice generation

The benchmark uses axial CT slices from approximately 8,000 lung tuberculosis patients. Images are provided as 256 × 256 grayscale PNG files.

## Task 1: Detect Training Data Usage

**Notebook:** `Task1_GANs_Detect_training_data_usage.ipynb`

Task 1 asks whether a given real CT image was used during the training of a generative model.

### Objective

For each real image in the test set, predict:

* `1` if the image was used during generator training
* `0` if the image was not used during generator training

### Method

The notebook implements a feature-based membership-inference pipeline using:

* spectral features
* intensity statistics
* histogram descriptors
* edge-based features
* deep ResNet distance features
* shadow-autoencoder reconstruction features
* classical machine learning ensembles
* out-of-fold validation
* threshold-based final prediction

### Result Summary

The internal validation ROC AUC reached approximately `0.7557`, suggesting some development-set separability. However, the official test performance did not generalise well.

Best official Cohen’s κ:

```text
-0.0290
```

### Key Lesson

The result shows that internal validation can be misleading when the threshold is tuned on the same out-of-fold predictions used for evaluation. It also highlights the fragility of membership-inference features under hidden test distribution shift.

## Task 2: Identify Corresponding Latent Vectors

**Notebook:** `Task_2_ImageCLEFmed_GANs_2026_Identify_corresponding_latent_vectors.ipynb`

Task 2 asks participants to match each synthetic CT image to the exact 128-dimensional latent vector that generated it.

### Objective

Given:

* 10,000 synthetic images
* 10,000 unordered latent vectors

predict the correct image-to-latent assignment.

### Method

The notebook implements a contrastive image-latent matching pipeline using:

* ConvNeXt-Base image encoder
* latent-vector MLP encoder
* shared embedding space
* memory-bank InfoNCE loss
* cosine similarity matrix
* CSLS reweighting
* Sinkhorn normalisation
* mutual-kNN boosting
* Hungarian matching

### Result Summary

The best official submission recovered:

```text
224 / 10,000 correct matches
```

Official accuracy:

```text
2.24%
```

This was above random chance but not strong enough for reliable exact latent recovery.

### Key Lesson

The held-out validation curve correctly predicted weak generalisation, while full-pool development accuracy was overly optimistic because it included many training images. The task demonstrates how latent-space privacy leakage can be difficult to measure honestly without strict validation separation.

## Task 3: Privacy-Preserving CT Slice Generation

**Notebook:** `ImageCLEFmed_GANs_2026_Privacy_preserving_CT_slice_generation.ipynb`

Task 3 asks participants to generate synthetic CT slices while reducing leakage under official privacy attacks.

### Objective

Generate 5,000 synthetic CT slices that preserve broad CT structure while reducing memorisation and patient-specific leakage.

### Method

The notebook trains a compact privacy-oriented DCGAN-style generator with:

* 128-dimensional Gaussian latent input
* compact generator architecture
* weak discriminator
* GroupNorm instead of BatchNorm
* strong zero-centred R1 regularisation
* exponential moving average generator weights
* patience-based early stopping
* 256 × 256 grayscale CT output

### Official Privacy Result

| Metric                            |  Value |
| --------------------------------- | -----: |
| Privacy Preservation Score        | 0.9086 |
| CT-specific FID                   | 3.2358 |
| NND leakage                       | 0.0213 |
| Membership inference leakage      | 0.1832 |
| Patient re-identification leakage | 0.1611 |
| White-box inversion leakage       | 0.0000 |

### Interpretation

The model achieved strong empirical privacy under the benchmark attacks, especially for nearest-neighbour leakage and white-box inversion. However, membership inference and patient re-identification remained above chance.

This means the model reduced direct instance-level memorisation, but did not fully eliminate distributional or patient-identity signals.

The strong privacy result also came with a fidelity cost. The generated CT slices preserve broad anatomical structure but show visible smoothing and reduced fine detail.

## Main Findings

The project supports three main conclusions:

1. **Empirical privacy is possible, but not free.**
   The Task 3 generator achieved strong privacy scores, but at the cost of reduced image fidelity.

2. **Empirical privacy is not differential privacy.**
   The method does not provide a mathematical privacy guarantee. It only demonstrates low leakage under the benchmark’s official attacks.

3. **Validation protocol matters.**
   Tasks 1 and 2 show that optimistic internal metrics can fail when validation data or threshold selection leaks information about the target quantity.

## Limitations

This repository does not provide formal privacy guarantees.

The Task 3 model does not use:

* DP-SGD
* differential privacy accounting
* formal privacy budgets
* certified privacy mechanisms

Known limitations include:

* reduced CT image fidelity
* remaining membership-inference leakage
* remaining patient re-identification leakage
* threshold sensitivity in Task 1
* development-set optimism in Task 2
* need for controlled privacy–utility sweeps

## Future Work

Possible extensions include:

* running a full privacy–utility frontier sweep
* testing different R1 regularisation strengths
* comparing GroupNorm and BatchNorm
* adding a matched-fidelity vanilla DCGAN baseline
* improving CT fidelity while preserving low leakage
* adding formal DP-SGD baselines
* improving Task 1 calibration
* improving Task 2 validation isolation and latent inversion robustness
